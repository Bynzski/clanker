# Assistant attention

Opened local Hermes Assistant surfaces expose Working, Needs input, Finished and Error in the sidebar and compact roster. Availability remains separate from activity. No Workspace, terminal broker identity or checkout authority is created for an Assistant.

Main subscribes to the authenticated `/api/events?channel=...` sidecar before opening `/api/pty` with the same stable channel. The channel follows the existing keep-alive attach identity. Native resume responses or `session.info` bind the runtime session to the canonical stored Bot Chat; other sessions cannot change its status. Only small status enums cross IPC. Prompts, request arguments, responses, native IDs and tokens do not.

Contract inspected in installed NousResearch/hermes-agent commit `bf0203a794a07aac3ff764972ab9087baa4e4f4e`: `hermes_cli/web_routers/chat_ws.py`, `tui_gateway/event_publisher.py`, `transport.py`, `server_requests.py`, and `contracts/events.py`. The sidecar mirrors JSON-RPC envelopes, including resume responses and server requests. `message.start` and root model `message.delta` indicate execution; `approval`, `clarify`, `sudo`, `secret`, `vault.unlock_prompt`, `vault.save_login` and `vault.code` requests indicate input; `request.cancel` withdraws a wait; `message.complete.status` distinguishes completion, error and interruption. Successful request responses are not mirrored, so Needs input can remain until the next model output or terminal outcome.

Connection loss clears status to unknown. Reconnection is bounded to one attempt per five seconds; frames are capped at 1 MiB and pending request bookkeeping at 64 entries. A five-second initial connection deadline prevents an unsupported sidecar from blocking chat. Disposal cancels retries, closes the observer and rejects stale callbacks. PTY output and keystrokes never establish activity.

The sidecar is best-effort and has no replay or publisher heartbeat. Unknown activity is not idle or finished; a silent publisher failure cannot be distinguished from a quiet long operation. Working/Needs input therefore expire to unknown after two minutes without root-session evidence; this does not imply completion. An existing keep-alive PTY created before this feature may have no publisher. It continues working unchanged, but attention requires a newly started Hermes PTY; Clanker does not terminate it to install observation. Restarting Clanker mid-turn can likewise leave activity unknown until native identity and lifecycle evidence arrives. This feature observes opened Bot Chats, not background cron jobs or every conversation in a profile.

Verification: observer tests cover canonical identity, child exclusion, lifecycle outcomes, all supported input methods, concurrent requests and root-scoped cancellation, frame bounds, timeouts, reconnect and stale callbacks. Service tests cover channel wiring and PTY teardown; renderer tests cover status presentation and connection loss. A real model-turn/native UI smoke has not been performed for this change.
